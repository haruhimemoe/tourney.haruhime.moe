# AGENTS.md

Rules for any agent (or human) working in this repo. Authoritative; `CLAUDE.md` only layers on top.

## 1. What this is

tourney.haruhime.moe runs an osu! tournament in one place. A host signs in, creates a lineage (the series) and an edition (one run of it), opens registration, approves players, builds teams, seeds and generates a bracket, schedules matches, enters results (by hand or from an mp link) and gets a public page at `/<lineage>/<edition>`. A player signs in, registers, sets availability and sees their next match on `/`. The specs live in the owner's notes; what users read lives in `README.md`, `content/docs/` and `content/legal/`, and section 7 says what has to stay in step with the code.

**Hard rule: we never host files.** No `.osz`, audio, image or video bytes pass through or are stored by our code. Mappools are linked from pools.haruhime.moe. The CSP in `next.config.ts` allows images from here, `data:` URIs, a.ppy.sh, osu.ppy.sh and assets.ppy.sh, and no media (`tests/unit/config/headers.test.ts`); a new image host needs a line there.

## 2. Layout

```
src/app/          routes only (thin; compose components)
src/components/   feature folders (account/, layout/, manage/, ...); primitives come from @haruhimemoe/ui
src/constants/    static data (site, db names, api limits, error messages, the content registry)
src/utils/        pure, stateless helpers grouped by domain
src/lib/          integration plumbing (db, auth, osu!, pools client, rate limits), wired from
                  @haruhimemoe/next-kit; account.ts is the hub session's browser half
src/services/     database work: every write calls a @haruhimemoe/tourney function and saves its result
src/schemas/      zod schemas: lib schemas .extend()ed for every stored shape, and the session user
content/          MDX docs and legal pages (content/docs, content/legal)
public/brand/     logos, icon and palette generated by @haruhimemoe/brand (never edited by hand)
tests/            unit/ (node), components/ (jsdom), integration/ (node + in-memory Mongo replica set), fixtures/, helpers/, setup/
```

## 3. Code style

- TypeScript 7, `strict`, `noUncheckedIndexedAccess`. No `any`; validate external data with zod.
- Biome is the only linter and formatter (`bun run check`, `bun run check:fix`).
- No barrel files in `src/`. Import exact local paths. npm packages are imported from their published entry points.
- One component per file, PascalCase filename, Tailwind only. Components are presentational; data lives in services. A component file exports only components and their prop types: copy goes in `src/constants/`, helpers in `src/utils/`.
- The native MongoDB driver only, no Mongoose. Every stored shape is a `@haruhimemoe/tourney` schema `.extend()`ed in `src/schemas/`; every rule check (phases, registration windows, team rules, brackets, seeding, schedules, pick/bans) is a lib call, never re-written here. Services return the lib's `Result`; `src/utils/result.ts` has the app's own `ok` and `fail`, since the lib exports only the types. Error codes are hyphenated like the lib's, and every code has a message in `src/constants/errors.ts`.
- Take what the shared packages have instead of copying it: server plumbing from `@haruhimemoe/next-kit` (route helpers, rate limits and the osu! budget, env, MongoDB and its indexes, the hub session reader, the account store and its menu), wired once in `src/lib/api.ts`, `rate-limit.ts`, `osu.ts`, `db.ts`, `db-indexes.ts`, `auth.ts`, `account.ts` and `src/env.ts`; UI pieces from `@haruhimemoe/ui`; time zones, availability and regions from `@haruhimemoe/time`; text formatting from `@haruhimemoe/osu/format`.
- Files stay under about 250 lines and components under about 200: split by what a part does. No import cycles in `src/`, type-only ones included.
- `utils/` is pure. Server-only modules `import "server-only"`. Client code never imports the `@haruhimemoe/osu` root (it holds the osu! secret); `tests/unit/tooling/client-imports.test.ts` enforces it.

## 4. File headers

Every `.ts`, `.tsx`, `.mjs`, and `.css` source file starts with:

```ts
/**
 * @file <repo-relative path>
 * @desc <what it is and why>
 * @author David @dvhsh (https://dvh.sh)
 * @created Ddd MMM D, YYYY
 * @modified Ddd MMM D, YYYY
 */
```

Dates match `date "+%a %b %-d, %Y"`. Update `@modified` on edits, never `@created`. Every export gets a doc comment right above it (one line is enough for a constant, type or schema); exported functions, components and route handlers get a JSDoc block with `@function`, `@param`, `@returns` (and `@throws` when they throw). `tests/unit/tooling/jsdoc.test.ts` checks every header and comment.

## 5. Tests

- Everything under `tests/`, mirroring `src/` paths. Write the failing test first.
- `bun run test` runs all three Vitest projects. The unit project runs with `TZ=America/Los_Angeles` on purpose.
- Tests never reach osu! or pools: msw (`setupMsw` from `@haruhimemoe/next-kit/testing`, `onUnhandledFrame: "error"`) with `tests/helpers/osu-server.ts`, or injected fakes. The fake env is next-kit's `TEST_OSU_APP_ENV` and `stubOsuAppEnv`; the in-memory MongoDB is a one-member `MongoMemoryReplSet` (`tests/setup/integration-global.ts`), so transactions work.
- Integration tests use `setupTestDb()` and build rows with the helpers in `tests/helpers/records.ts`. `tests/helpers/auth.ts` writes users and sessions straight into the `identity` database the way the hub would, and `setupTestDb()` empties those too.
- Coverage floor: 90% on `src/utils/**` and `src/schemas/**`.

## 6. Visual system

osu!-web look from `@haruhimemoe/ui`: `src/app/globals.css` imports its theme and pins `--hue: 110` (tourney's hue) and `--h2-l: 35%` (4.54:1 for white on h2 at that hue). Dark only. Font: Nunito. Page titles go through `PageHeader`; tables sit in an `overflow-x-auto` wrapper so phones scroll them.

`NEXT_PUBLIC_TOURNEY_BETA=true` (read by `isBeta()` in `src/lib/beta.ts`, written into the build by Next.js) shows a "beta" pill beside the header wordmark on every page. It changes nothing else.

## 7. Legal copy and docs

- Docs and legal pages are one registry, `CONTENT` in `src/constants/content.ts` (next-kit's `defineContent`): each entry is a slug, title, `navTitle` when the title is over 32 characters, description and `lastUpdated` (bump it with any wording change). tourney has no guides. A new page is three edits: the `.mdx` file, its registry entry and its line in `src/content/load.ts`; `tests/unit/content/registry.test.ts` fails until all three agree. The section routes under `src/app/{docs,legal}/` are copied from packs and identical apart from the section name; keep them that way. `/brand` is `<BrandPage {...brandPageData("tourney")} />`; its files come from `bunx haruhime-brand tourney`.
- A new per-IP or per-account counter goes in `privacy.mdx`. Every request our server makes to a third party is listed in `disclaimers.mdx` ("How our requests identify themselves").
- A change people see updates the README.
- No em dashes in any copy. osu! wiki text is CC BY-NC: paraphrase, never copy.

## 8. Commits and PRs

- Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `test:`, `refactor:`).
- Before pushing: `bun run check && bun run typecheck && bun run test && SKIP_ENV_VALIDATION=true bun run build`.
- When a change affects conventions, update this file in the same PR.
